# Ohio local ordinances and court rules

Generated corpus of municipal law and local court rules that can change the
outcome of an eviction. See [`docs/LOCAL_ORDINANCES.md`](../../docs/LOCAL_ORDINANCES.md)
for the full maintenance guide.

```text
scope.yaml                  # reviewable coverage: municipalities, targets, acquisition routes
datasets/                   # structured cross-city comparisons, one file per topic
to_ingest/                  # inbox: drop supplied text here, it is not read by anything
_transcriptions/            # supplied text that scope.yaml points a target at
  _source/                  # the original supplied file, kept as provenance
<municipality-slug>/
  manifest.yaml             # generated: sections (ingested and pending) and chunk inventory
  sections/<key>.md         # generated: the whole retrieved text, provenance-stamped
  chunks/*.md               # generated: retrieval-sized pieces
```

`scope.yaml` and `datasets/*.yaml` are maintained by hand and reviewed. Everything
else is generated by `scripts/ingest_local_ordinances.py`; do not hand-edit it.

Two rules carry most of the weight here:

- **Codifier sites are citation targets, never fetch targets.** American Legal
  Publishing and Municode both refuse automated retrieval. Text comes from the
  city's own legislative record (Legistar) or an official published document,
  and every record carries the codifier URL for verification.
- **A declared authority with no permitted retrieval route stays visible.** It is
  recorded as `pending` with the reason and produces no chunk, so retrieval can
  never return it as law while a reader is still told it exists. Every declared
  authority currently holds text, so nothing is pending today — the machinery
  stays because the next municipality added will be.

## Supplying text by hand

Where nothing here can reach a document, a person can. Drop what you have in
`to_ingest/`; nothing reads that folder. To put it in the corpus, move it to
`_transcriptions/<municipality>-<key>.md` with the frontmatter the existing
files use, keep the original alongside it in `_transcriptions/_source/`, and
point the target's `acquire:` block at it:

```yaml
        acquire:
          method: transcription
          file: _transcriptions/akron-pay-to-stay.md
          provided_by: <who supplied it>
          provided_on: '<date>'
          asserted_source: <where they say it came from>
```

Supplied text is stamped `unverified_transcription` and rechecked on the
shortest cadence, whether it was typed out or pasted from a codifier, because
nothing here read it off a publisher's page. That stamp is not a judgement about
the text: a codifier's rendering of the section in force is often the best
statement of the current rule available, and better than the enacting act for
answering what the rule is today. Set `verified: true` in the file's frontmatter
once a person has checked it against the `verification_urls`.

A supplied copy does not displace a retrieved one. Where both exist, the
retrieved document stays the record and the supplied copy is kept as a
comparison, with what the comparison showed written into the target's `notes`.
